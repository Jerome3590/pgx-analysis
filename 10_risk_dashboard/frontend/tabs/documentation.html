Documentation

Overview

This dashboard supports F1120 Opioid ED Visit risk and Polypharmacy risk. Each cohort supports age bands 13–114 (13-24, 25-44, 45-54, 55-64, 65-74, 75-84, 85-114). Use the Opioid ED or Polypharmacy tab to switch cohort; age selects the age band within that cohort.

Tabs

Cohort selector (top row): Opioid ED | Polypharmacy — switches cohort and loads cohort-specific metadata. Both cohorts support age bands 13–114.

Primary tabs (second row): User Guide | Risk Assessment | Drugs | ICD Codes | CPT Codes | PGx Card. Drugs / ICD / CPT use an italic label to mark user-selected codes.

Visualization tabs (third row): Feature Importance | Scenario Analysis (FFA/SHAP) | BupaR Process Mining | DTW Trajectories | FP-Growth Patterns | Drug Networks | PGx Cohort

  • Risk Assessment — Enter age, select codes (via Drugs / ICD / CPT tabs), then click Calculate Risk Score. Use Replace / swap to exchange a selected drug, ICD, or CPT, then recalculate. Save two or more code sets and use Compare Scenarios for side-by-side ensemble risk (empty baseline vs current remains the default when nothing is saved). Drug contributions shows leave-one-out Δp̂ for each selected drug. After calculation, an Event Density badge (low / medium / high / extreme) appears — this bin is auto-synced to all visualization tabs to load patient-matched per-bin data.
  • Drugs — Search and add drugs for your patient. Selections are used for the risk calculation. A visual display shows all selected drugs with option to remove them.
  • ICD Codes — Search and add ICD codes for your patient. Used for risk in the Opioid ED cohort only.
  • CPT Codes — Search and add CPT codes for your patient. Used for risk in the Opioid ED cohort only.
  • PGx Card — Claims radar (Load Cohort PGx Profile) plus an exploratory card from consumer raw DNA (Generate PGx results). Array files report detected variants and gene coverage. They do not assign a diplotype, metabolizer status, or dose. Lab Gene,Allele lines still use the official phenotype table.
  • Feature Importance — Aggregated feature importance heatmaps by cohort (from Step 3a / 2_feature_importance).
  • Scenario Analysis (FFA/SHAP) — View FFA interaction factors and SHAP importance by cohort, age band, and event density bin. Filterable by patient codes. These charts do not recalculate ensemble risk — use Risk Assessment compare / replace for modeled probabilities.
  • BupaR Process Mining — Process mining, activity frequency charts, and Gantt visualizations. Includes Activity Rate by Event Density Bin panel (grouped bar / heatmap toggle).
  • DTW Trajectories — Dynamic time warping trajectory visualizations by cohort, age band, and event density bin.
  • FP-Growth Patterns — Frequent itemset and drug association network visualizations. Includes Itemset Support by Event Density Bin panel (grouped bar / heatmap toggle).
  • Drug Networks — Interactive Drug Networks (Cytoscape) graph of feature-importance–filtered FP-Growth rules (same FI-gated set as FP-Growth, not Plotly). Cohort × age band; combined train window. Click Load Drug Network.
  • PGx Cohort — PGx gene network topology and citation radar for the selected cohort and age band.

  • RQ2 (Opioid ED) — What CPT/ICD codes and drugs predict OPIOID_ED? Predictive sequences? Feature importance? High-risk trajectories? Formal causality? → FP-Growth + Scenario Analysis (FFA/SHAP) (itemsets, network, FFA, SHAP), BupaR (top sequences, pre-target frequency), DTW Trajectories (trajectory overview, high-risk vs low-risk).

How to use (use cases)

Compact map of what each persona can do. The full numbered workflows (live button names) live in the repo: 10_risk_dashboard/docs/DASHBOARD_USE_CASES.md (GitHub). A relative markdown path will not load on this static site.

  1. Clinician / pharmacist — score and compare. Set Opioid ED or Polypharmacy, enter Age, add Drugs (and ICD Codes / CPT Codes for Opioid ED), then Calculate Risk Score. Use Replace / swap, save two or more sets and Compare Scenarios (or empty baseline vs current), and Drug contributions (LOO Δp̂). Then View PGx Card →.
  2. Scenario Analysis (FFA/SHAP) explains drivers; it does not recalculate ensemble risk. Use Risk Assessment for modeled p̂.
  3. After a score, the Event Density badge (low / medium / high / extreme) auto-syncs BupaR Process Mining, DTW Trajectories, FP-Growth Patterns, PGx Cohort, and PGx Card Event Density. Those research tabs are not filtered by your selected codes (Scenario Analysis charts are the exception).
  4. Researcher path: Feature Importance + Scenario Analysis (FFA/SHAP) + BupaR / DTW / FP-Growth / Drug Networks / PGx Cohort. RQ → artifact table is in repo 10_risk_dashboard/docs/RESEARCH_QUESTIONS_ARTIFACTS.md (GitHub).
  5. PGx Card (claims): Load Cohort PGx Profile — radar is cohort/claims, not genotype. Scopes: Active medications / Selected drugs / All matched drugs. Triplets are regimen-only (≥ 3 meds). Actionable only hides standard / no-CPIC rows.
  6. PGx Card (DNA): AncestryDNA, 23andMe, and MyHeritage are genealogy arrays. They show which variants were typed, not which chromosome copy each variant is on, and they do not measure copy number. A prescribing claim needs both, so the card reports detected variants, gene coverage, and whether a clinical test is warranted. It does not assign a diplotype, metabolizer status, or dose. Missing sites are Data Not Present in File and are not called *1. A lab line such as CYP2C19,*1,*2 still uses the official phenotype table. Exports include a physician summary PDF. Send to pharmacy is disabled.
  7. PGx Cohort is population topology; PGx Card is the patient/session card.

Workflow

  1. Set Age on Risk Assessment (this loads metadata and determines age band; age 13–114 supported for both cohorts).
  2. Open Drugs tab, search and add the drugs you need. View selected drugs in the display area.
  3. For the Opioid ED cohort, also open ICD Codes and CPT Codes tabs to add additional codes.
  4. Return to Risk Assessment and click Calculate Risk Score.
  5. Use Replace / swap to exchange a selected code, then Calculate Risk Score.
  6. Save two (or more) code sets and use Compare Scenarios to score them side-by-side. Leave Include empty baseline checked to also show the 2019 population baseline. With no saved sets, Compare is baseline vs current selection.
  7. Use Drug contributions to see leave-one-out Δp̂ when each selected drug is removed.
  8. After risk calculation, note the Event Density badge (low / medium / high / extreme). Visualization tabs auto-sync to this bin, loading patient-matched density data automatically.
  9. Explore visualizations on other tabs (Scenario Analysis, DTW, etc.) to understand feature importance and patterns. Scenario Analysis charts are FFA/SHAP signals, not new ensemble risk scores.

Feature importance sources for visuals

BupaR, DTW, and FP-Growth use different feature-importance inputs:

  • BupaR Process Mining and DTW Trajectories use SHAP/FFA combined — allowed codes (drug, ICD, CPT) come from merged SHAP and FFA causal importance (Steps 7 and 8). The pipeline writes these to a single allowed-codes file per cohort/age band; R (BupaR) and Python (DTW) use that list only.
  • FP-Growth Patterns use final feature importances — allowed items come from the cohort feature importance list (Step 3b, refined/leakage-filtered). FP-Growth does not use the SHAP/FFA combined list.

So: BupaR and DTW visuals are driven by SHAP/FFA combined; FP-Growth visuals are driven by the final (cohort) feature importance list.

Event density bins — what #events means and how bins work

#events is the total count of distinct drug, ICD, and CPT codes you submit for the patient. For example: 3 drugs + 4 ICD codes + 2 CPT codes = 9 events. This count is compared against percentile thresholds derived from the training population (P25 / P50 / P95) for that specific cohort and age band, and mapped to one of four density bins:

BinRuleClinical meaning
low#events ≤ P25Sparse history — few prior utilization records
mediumP25 < #events ≤ P50Typical outpatient utilization
highP50 < #events ≤ P95Complex, high-utilization patient
extreme#events > P95Highest-complexity stratum — very high prior utilization

Sample thresholds (opioid_ed / 25-44, approximate):

BinApproximate #events rangePercentile cut
low1 – 5 codes≤ P25
medium6 – 15 codesP25 – P50
high16 – 50 codesP50 – P95
extreme51+ codes> P95

Thresholds are computed from the training cohort distribution (P25/P50/P95 of per-patient event counts in model_events.parquet) and vary by cohort and age band. The values above are representative defaults — actual cuts differ per cohort/age band.

Why it matters: Separate XGBoost and CatBoost models are trained and Optuna-tuned independently per bin. Risk scores, causal factors, DTW trajectories, FP-Growth patterns, and BupaR process views all load the per-bin data matching the patient's density level. After clicking Calculate Risk Score, the Event Density badge shows the patient's bin and all visualization tabs auto-sync to it.

Unphased DNA files and star alleles

Genealogy files (AncestryDNA, 23andMe, MyHeritage) and a typical unphased VCF cannot support a clinical pharmacogenomic claim. They were built to report which variants are present. They do not say which copy of the gene each variant sits on, and they do not measure copy number. CPIC dosing uses a phased diplotype plus copy-number validation. A site that is absent from the file is not a normal allele.

The card can report a detected variant, gene coverage, and whether a clinical test is warranted. It does not assign a diplotype, a metabolizer status, or a dose from that file.

  • Permitted: “Variant rs12248560 (C/T) detected in raw upload file.” “Gene Coverage: 42% of known CYP2D6 variant locations present.” “CPIC guideline reference available for clopidogrel.”
  • Not produced from array files: a star-allele diplotype, a metabolizer status, or a dose change.
  • A site missing from the file is marked Data Not Present in File. It is not filled in as *1.

Entering a lab-reported line such as CYP2C19,*1,*2 skips this raw-file path and uses the official diplotype-to-phenotype table.

Technical notes

The backend uses an ensemble of CatBoost, XGBoost, and XGBoost RF models. Metadata (drugs, ICD, CPT) is filtered by cohort and age band. All tabs use the same page; nothing here navigates you away to a separate doc page.

Note for Polypharmacy cohort: Only drugs are used for risk calculation. ICD and CPT code tabs are hidden for this cohort. Both cohorts support age bands 13–114.
